# 크게 보고 작게 착지하기 — 철학·사회·심리 렌즈로 여는 청소년 프로젝트

> 앞선 문서([바이브코딩_아이디어_50선](바이브코딩_아이디어_50선.md))가 "무엇을 만들까"였다면,
> 이 문서는 **"왜 그게 문제인가"** 를 다룬다.
> 심사위원이 던지는 세 질문 중 가장 답하기 어려운 것 — *"이 주제를 잡은 이유는 무엇인가요?"* 에 대한 무기.

---

## 0. 전제: 큰 질문은 출발점이지 제출물이 아니다

앞서 "AI로 환경 문제 해결 같은 거대 담론은 피하라"고 썼다. 그 말은 여전히 유효하다.
하지만 그건 **크게 생각하지 말라는 뜻이 아니라, 크게 생각한 것을 작게 착지시키라는 뜻**이다.

```
철학적 질문 (왜 이게 문제인가)
        ↓  좁힌다
사회적 현상 (누구에게, 어떤 상황에서 일어나는가)
        ↓  좁힌다
심리적 기제 (그 사람 머릿속에서 무슨 일이 벌어지는가)
        ↓  좁힌다
관찰 가능한 행동 (숫자로 셀 수 있는 것)
        ↓  만든다
화면 3장짜리 프로토타입
```

발표는 이 순서를 **거꾸로** 한다. 프로토타입을 먼저 보여주고, 마지막 30초에 큰 질문으로 올라간다.
그래야 "말만 거창한 애"가 아니라 "깊이 있는 애"가 된다.

## 1. 철학 렌즈 — 개념을 의심하기

철학이 하는 일은 **모두가 당연하게 쓰는 단어를 멈춰 세우는 것**이다.
프로젝트에서 이 태도는 곧 *"판정 기준을 무슨 근거로 정했는가"* 라는 심사 질문에 대한 답이 된다.

### 1-1. "공정하다"는 게 뭔가
- **질문**: 모두에게 똑같이 주는 게 공정인가, 필요한 만큼 주는 게 공정인가?
- **현장**: 모둠 점수, 자리 배치, 급식 배식량, 동아리 선발, 청소 당번
- **착지**: *모둠 기여도 기록판*을 만들되, **공정 기준을 3가지 모드로 전환**할 수 있게 한다.
  균등분배 / 투입시간 비례 / 결과물 기여 비례 — 같은 데이터가 모드마다 다른 결론을 낸다는 걸 보여준다.
- **왜 강한가**: "정답 하나를 계산하는 앱"이 아니라 **"정답이 여러 개임을 드러내는 앱"** 이다. 심사에서 차별성이 크다.

### 1-2. 기억하지 않을 권리
- **질문**: 인터넷은 잊지 않는다. 잊힐 수 없다면 우리는 자유로운가?
- **현장**: 초등학교 때 올린 게시물, 단톡방 캡처, 졸업사진, 검색되는 내 이름
- **착지**: *디지털 발자국 자가진단* — 내 이름·아이디로 공개 검색되는 흔적을 스스로 점검하는 체크리스트 웹.
  (실제 검색을 대행하지 말 것. **본인이 직접 확인하도록 안내하는 도구**로 설계 — 이게 윤리적으로도 안전하다)
- **연결**: EU '잊힐 권리', 한국 '디지털 잊힐 권리 지우개 서비스'(만24세 미만 대상) 조사해 붙이면 사회 맥락이 생긴다.

### 1-3. 진짜와 가짜의 경계
- **질문**: AI가 만든 그림·글·목소리는 '가짜'인가? 무엇이 그것을 가짜로 만드는가 — 만든 주체인가, 속이려는 의도인가?
- **착지**: *출처 표시 배지 생성기*. 창작물에 "AI 100% / AI 보조 / 사람 100%" 라벨을 붙이는 표준을 직접 제안하고, 그 라벨을 이미지에 합성해주는 웹.
- **왜 강한가**: 규제를 요구하는 대신 **작은 규약을 스스로 만들어 배포**하는 접근. 창업 대회의 '차별성' 항목에 정확히 걸린다.

### 1-4. 측정이 대상을 바꾼다 (굿하트의 법칙)
- **질문**: 어떤 지표가 목표가 되는 순간, 그 지표는 좋은 지표이기를 멈춘다.
- **현장**: 내신 등급, 봉사시간, 팔로워 수, 독서 권수, 걸음 수
- **착지**: *지표 왜곡 시뮬레이터*. "독서 권수로 평가하면 얇은 책만 읽는다"를 슬라이더로 조작해 보여주는 인터랙티브 웹.
- **왜 강한가**: 만들기 쉬운데(★★) 통찰이 크다. 시뮬레이션은 데이터 수집 부담도 없다.

### 1-5. 도구가 사람을 만든다
- **질문**: 우리가 도구를 쓰는가, 도구가 우리를 쓰는가?
- **착지**: *내 앱 사용시간 vs 내가 생각하는 사용시간* 비교 기록. 인식과 실제의 격차를 그래프로.
- **연결**: 니체·하이데거까지 갈 필요 없다. "망치를 들면 모든 게 못으로 보인다"는 한 문장이면 충분하다.

## 2. 사회 렌즈 — 구조를 보기

개인의 잘못으로 보이는 일이 사실은 **구조의 결과**일 때가 많다.
사회 렌즈는 "누가 이 문제를 겪는가, 왜 하필 그 사람인가"를 묻는다.

### 2-1. 보이지 않는 노동
- **현상**: 아무도 안 하면 티가 나지만, 하면 티가 안 나는 일. 총무, 단톡방 공지, 집안일, 감정 돌봄.
- **착지**: *보이지 않는 일 가시화 로그*. 팀·가족 안에서 "티 안 나는 일"만 골라 기록하고 월말에 파이차트.
- **데이터**: 우리 집 2주 기록이면 충분하다. 표본이 작아도 **직접 수집했다는 사실**이 점수다.

### 2-2. 접근성은 소수의 문제가 아니다
- **현상**: 경사로는 휠체어만을 위한 게 아니다. 유모차, 캐리어, 배달 카트, 다친 사람이 쓴다.
- **개념**: **커브컷 효과(curb-cut effect)** — 소수를 위한 설계가 결국 모두를 이롭게 한다.
- **착지**: *우리 동네 커브컷 지도*. 계단 없는 경로를 제보로 모으고, "이 경로의 수혜자"를 휠체어·유모차·캐리어·자전거로 태깅.
- **왜 강한가**: 사회적 의미 + 지도라는 명확한 산출물 + 확장 가능성. 사업화 항목까지 답이 나온다.

### 2-3. 정보 격차는 나이에서 온다
- **현상**: 같은 공문을 부모는 읽고 조부모는 못 읽는다. 키오스크 앞에서 줄이 멈춘다.
- **착지**: *공공 안내문 쉬운말 변환기* + **어려운 단어 사전을 학생들이 직접 채우는** 위키.
- **연결**: '쉬운 말 운동(Plain Language)', 국립국어원 쉬운 공공언어 쓰기 지침.

### 2-4. 공유지의 비극
- **현상**: 모두의 것은 아무의 것도 아니다. 교실 뒷정리, 공용 우산, 학교 공유 태블릿, 동네 공원.
- **착지**: *공용물 상태 기록판* — 마지막 사용자·상태를 남기면 다음 사람이 본다. 익명성을 걷어내는 것만으로 행동이 바뀌는지 2주 실험.
- **핵심**: 이건 **앱보다 실험이 주인공**이다. "익명일 때 vs 기록될 때" 비교 데이터가 곧 결과물.

### 2-5. 알고리즘이 만드는 세계
- **현상**: 추천 알고리즘은 내가 좋아할 것을 주는 게 아니라, 내가 머무를 것을 준다.
- **착지**: *내 추천 피드 해부하기*. 하루 동안 뜬 추천 영상 제목을 직접 기록 → 주제 분포 그래프 → "내 세계는 얼마나 좁은가" 지수.
- **왜 강한가**: 플랫폼 API 없이 **손으로 기록한 데이터**로 성립한다. 데이터 확보 리스크가 0.

### 2-6. 규칙은 누가 만드는가
- **현상**: 교칙, 단톡방 규칙, 게임 커뮤니티 규칙 — 지키는 사람과 만드는 사람이 다르다.
- **착지**: *학급 규칙 합의 도구*. 규칙안을 올리고 찬반이 아니라 **"내가 못 받아들이는 정도"** 를 0~5로 표시 → 총 반대강도가 최소인 안을 찾는 방식(동의 기반 의사결정).
- **왜 강한가**: 다수결의 한계를 다루는 정치철학이 그대로 UI가 된다.

## 3. 심리 렌즈 — 머릿속 기제를 다루기

심리학은 **"왜 알면서도 안 하는가"** 를 설명한다. 이게 프로젝트의 핵심 동력이 된다.

### 3-1. 계획 오류 (planning fallacy)
- **기제**: 사람은 언제나 자기가 걸릴 시간을 과소평가한다.
- **착지**: *내 시간 예측 정확도 트래커*. 수행평가·숙제를 시작 전 예상시간과 실제시간으로 기록 → 개인 보정계수(예: 1.7배) 산출 → 다음부터 자동 보정.
- **왜 좋은가**: 사용자 = 나. 데이터 = 내 기록. 결과 = 숫자. 셋 다 자급자족된다. 난이도 ★★.

### 3-2. 사회적 증거와 침묵의 나선
- **기제**: 다들 괜찮아 보이면 나만 이상한 줄 안다. 실제로는 다수가 불편한데 아무도 말하지 않는다. (다원적 무지)
- **착지**: *익명 온도 체크*. 학급에서 "이 상황 불편한 사람?"을 익명 집계해 **분포만** 보여준다. 개인은 드러나지 않고 다수의 실제 생각만 드러난다.
- **주의**: 설계 윤리가 곧 발표 포인트다. 누구도 특정되지 않게 하는 최소 응답 수 설정 같은 안전장치를 넣고 그걸 설명하라.

### 3-3. 손실 회피
- **기제**: 얻는 기쁨보다 잃는 고통이 2배 크다.
- **착지**: *습관 유지 앱을 '연속 기록' 대신 '복구 가능'으로 설계*. 스트릭이 끊길 때의 좌절이 오히려 포기를 부른다는 가설을 세우고, 두 버전을 친구들에게 나눠 2주 A/B 테스트.
- **왜 강한가**: **가설 → 실험 → 데이터**. 한국코드페어처럼 연구 성격이 있는 대회에 정확히 맞는다.

### 3-4. 주의력은 유한한 자원이다
- **기제**: 알림 하나가 끊은 집중은 되돌아오는 데 평균 수 분이 걸린다.
- **착지**: *알림 부검 일지*. 하루 동안 받은 알림을 "지금 필요했다 / 나중에도 됐다 / 아예 필요 없었다"로 분류 → 주간 리포트 → 끌 알림 추천.
- **확장**: 이 데이터로 "내 하루에서 진짜 필요한 알림은 12%였다" 같은 문장이 나오면 발표가 산다.

### 3-5. 비교는 어디서 오는가
- **기제**: 상향 비교는 동기를 주기도, 무너뜨리기도 한다. SNS는 남의 하이라이트와 내 일상을 비교시킨다.
- **착지**: *하이라이트 대 일상 갤러리*. 같은 하루를 "올릴 만한 사진 1장"과 "안 올릴 사진 5장"으로 나란히 기록하는 앱. 한 달 뒤 두 줄기를 나란히 보여준다.
- **성격**: 기능이 아니라 **경험을 설계하는 프로젝트**. 예술·인문 성향 심사에서 강하다.

### 3-6. 자기결정이론 — 자율·유능·관계
- **기제**: 사람은 스스로 정할 때, 늘어남을 느낄 때, 연결될 때 지속한다.
- **착지**: 기존 학습 앱을 이 3요소로 **평가하는 체크리스트 도구**를 만든다. 앱을 만드는 대신 **앱을 심사하는 앱**.
- **왜 강한가**: 남들이 앱을 만들 때 혼자 기준을 만든다. 창의성·차별성 항목에서 튄다.

### 3-7. 도덕적 이탈 (moral disengagement)
- **기제**: 온라인에서 사람은 상대를 사람으로 덜 느낀다. 익명성·거리감·책임 분산.
- **착지**: *댓글 쓰기 전 1초 장치*. 공격적 표현이 감지되면 "이 말을 얼굴 보고 할 수 있나요?"를 띄우고 3초 대기. 실제로 전송률이 얼마나 떨어지는지 친구들과 실험.
- **선행 사례**: 삼성 주니어 SW 대회 중등부 수상작이 정확히 이 계열(욕설 차단, 악성글 탐지). **차별점은 '차단'이 아니라 '지연'** 이라는 데 있다.

## 4. 세 렌즈를 하나로 겹치면 — 통합 예시 3개

### 통합 A. "잊힐 권리" 프로젝트
| 층위 | 내용 |
|---|---|
| 철학 | 기록이 영원할 때 사람은 변화할 수 있는가 |
| 사회 | 미성년기 게시물이 성인기 평판이 되는 구조, 지우개 서비스의 존재 |
| 심리 | 과거의 나와 현재의 나를 동일시하는 정도(자기 연속성) |
| 산출물 | 디지털 발자국 자가진단 체크리스트 + 또래 100명 설문 "지우고 싶은 게시물이 있는가" |
| 난이도 | ★★ |

### 통합 B. "보이지 않는 일" 프로젝트
| 층위 | 내용 |
|---|---|
| 철학 | 가치 있는 일과 눈에 보이는 일은 왜 다른가 |
| 사회 | 가사노동·돌봄노동의 비가시성, 모둠 무임승차 |
| 심리 | 자기 기여를 과대평가하는 경향(가용성 편향) — 가족 각자에게 "내 기여 %"를 물으면 합이 100을 넘는다 |
| 산출물 | 기여 기록판 + "우리 가족 합계 %는 몇이었나" 실험 결과 |
| 난이도 | ★★ |
| 강점 | **합이 100을 넘는다**는 한 장의 그래프가 발표 전체를 끌고 간다 |

### 통합 C. "추천 알고리즘과 내 세계" 프로젝트
| 층위 | 내용 |
|---|---|
| 철학 | 내가 고른 것과 나에게 주어진 것을 구별할 수 있는가 |
| 사회 | 필터버블, 관심경제(attention economy) |
| 심리 | 확증편향, 무한 스크롤과 가변 보상 |
| 산출물 | 추천 피드 수기 기록 → 주제 다양성 지수 → 2주간 "일부러 다른 주제 시청" 개입 후 변화 측정 |
| 난이도 | ★★ |
| 강점 | 개입 전후 비교 = 실험 설계. 연구형 대회에 강함 |

## 5. 발표에서 큰 질문을 다루는 법

### 구조: 작게 시작해서 크게 끝난다
```
0:00  구체적 장면 하나   "지난 학기 모둠 발표에서 저는 새벽 2시에 혼자 PPT를 만들고 있었습니다"
0:30  숫자              "같은 경험, 우리 반 28명 중 19명이 있다고 답했습니다"
1:30  만든 것 시연       화면 3장
3:30  결과              "2주 써본 4개 모둠에서 기여도 인식 차이가 절반으로 줄었습니다"
4:30  큰 질문으로 상승    "공정하다는 건 똑같이 나누는 걸까요, 아니면 보이지 않는 것까지 세는 걸까요"
```

### 하면 안 되는 것
- 큰 질문으로 **시작**하기 → "말만 거창하다"는 인상이 첫 30초에 박힌다
- 철학자·이론 이름을 나열하기 → **개념 하나면 충분**하다. 이름은 몰라도 되고 현상을 설명할 수 있으면 된다
- 문제를 사회 탓으로 돌리고 끝내기 → 심사는 **해결 시도**를 본다
- 윤리적 위험을 언급 안 하기 → 익명 데이터, 미성년 대상 설문이면 **보호장치를 먼저 말하라**. 감점이 아니라 가점 요소다

### 반드시 준비할 답변
| 예상 질문 | 준비 |
|---|---|
| "이 주제를 왜 골랐나요?" | 개인적 장면 1개. 통계가 아니라 이야기로 |
| "판정 기준의 근거는?" | 왜 그 수치인지. "임의로 정했지만 이러이러해서 조정했다"도 좋은 답이다 |
| "이미 있는 서비스와 다른 점은?" | 개념 자체를 다르게 정의했다는 점을 말하라 |
| "표본이 너무 적지 않나요?" | 한계를 먼저 인정하고, **다음 단계 설계**를 말하라 |
| "이거 실제로 쓰이나요?" | 몇 명이 며칠 썼는지 숫자로 |

## 6. 윤리 체크리스트 (사람을 대상으로 하는 순간 필요)

- [ ] 응답자가 **누구인지 특정될 수 없는가** (최소 응답 수, 학급명 제거)
- [ ] 참여가 **자발적**인가 (거절해도 불이익 없음을 명시했는가)
- [ ] 민감정보(성적, 가정형편, 건강, 관계)를 **꼭 수집해야 하는가**
- [ ] 수집한 데이터를 **언제 지울 것인가**
- [ ] 친구를 평가·분류하는 도구라면, **당사자가 결과를 볼 수 있는가**
- [ ] AI 판정이 틀렸을 때 **사람이 뒤집을 수 있는가**

> 한국코드페어는 사람 대상 연구 시 **[서식4] 연구계획서 + [서식5] 연구 참가 동의서**를 실제로 요구한다.
> 윤리는 형식 요건이기도 하다.

## 7. 한 문장 요약

> **거대한 질문을 품되, 제출하는 것은 화면 세 장과 2주치 데이터여야 한다.**
> 심사위원이 감동하는 지점은 아이디어의 크기가 아니라 **큰 질문과 작은 증거 사이의 거리를 스스로 좁혀낸 흔적**이다.
