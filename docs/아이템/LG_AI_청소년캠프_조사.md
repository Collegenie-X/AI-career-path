## 1. 한 줄 요약
LG디스커버리랩 + 서울대학교가 함께 운영하는 **무료** 청소년 AI 교육 프로그램.
"AI 기술 학습"보다 **"내 주변의 문제를 발견하고 AI로 해결하는 아이디어"** 에 압도적으로 비중을 둔다.

## 3. 지원 방식 — 여기가 핵심

### 제출물
1. **역할 선택**: 기획자 / 개발자 (중복 선택 가능)
2. **아이디어 영상 (1~3분)** — 유튜브 '일부공개' 업로드 후 URL 제출
3. 영상 자막(스크립트) 추출본
4. 영상 원본 파일 (1GB 이하)
5. 역할 소개서 (사이트에서 양식 다운로드)

### 영상 필수 요건
- **지원자 본인이 직접 출연** (얼굴 + 목소리)
- 일상에서 **왜 그 문제를 발견했는지** 설명
- **AI로 어떻게 해결할지 나만의 아이디어를 구체적으로** 설명
- 선택한 **역할(기획자/개발자)에 맞추어** 설명할 것
- ChatGPT 등 **AI 도구를 썼다면 어떻게 썼는지 밝힐 것** (감점이 아니라 공개 의무)

## 4. 심사 기준 (5개 항목)
1. **AI에 대한 관심**
2. **사회 문제의 참신성** ← 아이디어의 독창성
3. **협업 의지**
4. **열정과 태도**
5. **팀 프로젝트 역할별 역량 및 경험**

> 코딩 실력·수상 경력·성적을 직접 묻지 않는다. 기술 스펙이 아니라
> **문제 발견력 + 아이디어의 참신성 + 팀으로 끝까지 갈 사람인가**를 본다.

## 5. 비중이 실린 지점 (분석)

### (1) "기술"보다 "문제 정의"
전 과정의 출발점이 *일상에서 발견한 진짜 문제*다. 지원 영상부터 서울대 합숙의 팀 주제 탐색,
온라인 프로젝트의 결과물까지 동일한 축으로 이어진다. → **디자인씽킹 기반.**

### (2) 개인 아이디어 → 팀 프로젝트로 전환
선발은 개인 영상으로 하지만, 이후 3개월은 전부 팀 단위다.
그래서 심사 항목에 *협업 의지*와 *역할별 역량*이 들어가 있고,
지원 단계부터 **기획자/개발자 역할을 스스로 정의**하게 만든다.

### (3) 지속성·성실성을 강하게 요구
- 합숙(2박3일) 및 최종 발표일 **필수 참석**
- 온라인 팀 프로젝트 **80% 이상 출석** + 최종 결과물 제출 → 수료
- *"다른 교육 일정으로 인한 결석도 결석 처리"* — 유예 없음
→ 반짝이는 아이디어보다 **끝까지 완주할 팀원**을 뽑겠다는 신호.

### (4) 경쟁과 보상 설계
- 상위 15명만 미국 과정 진출 (대체 프로그램 없음)
- **LG인재상**(최고상), **최다 응모 학교상**(학교당 100만원) 시상
→ 개인 동기 + 학교 단위 확산을 동시에 노림.

### (5) 접근성
전 과정 **무료**(사회공헌), 비수도권 참가자 **교통비 지원**.
초6~중2 대상이라 진입 장벽을 의도적으로 낮춤.

## 6. 지원 대상
초등 6학년 ~ 중학교 2학년 (3기 기준, 2025년 학년 기준)

## 7. 지원 전략 시사점
- 영상은 **"기술 자랑"이 아니라 "문제 스토리텔링"** 으로 구성 — 왜 이 문제가 나에게 절실한가부터.
- AI 해결 방식은 **막연한 "AI로 자동화"가 아니라 구체적 동작 시나리오**로.
- 기획자/개발자 역할을 고르되, 그 역할로 **팀에 무엇을 기여할지** 명시.
- 참신성 = 남들이 안 본 문제 > 어려운 기술.

## 12. 역할 기술서 문항 (원문)

**공통**
1. 나 자신을 소개해주세요. (300자 이내) — 성향, 관심사, 취미, 교내외 활동, 영향을 준 책과 이유 등
2. 팀 프로젝트는 4명이 한 팀입니다. 나와 다른 성향·능력을 가진 팀원들과 어떻게 협업할지 구체적으로. (300자 이내)

**기획자 선택 시**
3. 기획자로서 자신의 특기와 장점 (500자 이내)
4. 그 특기·장점을 살린 경험을 구체적으로 (500자 이내)
   - 예시: 글쓰기(시/에세이/일기), 발명, 자원봉사, 인터뷰·시장조사, 구체적 계획(상품 기획·일정 조정), 디자인, 발표 경험

**개발자 선택 시**
3. 개발자로서 자신의 특기와 장점 (500자 이내)
4. 그 특기·장점을 살린 경험을 구체적으로 (500자 이내)
   - **필수 기재: 개발 언어 / 개발 툴(이름 및 버전) / 구현한 기능**

> 기획자·개발자 중복 선택 시 **양쪽 문항을 모두** 작성해야 하고, 영상에서도 **두 역할 모두** 설명해야 한다.

### 팀 프로젝트에서의 역할 정의 (요강 원문)
- **기획자**: 문제 찾기 사전조사 / 경험을 살린 아이디어 제안 / 전문 지식 조사로 해결 방안 구체화 / 협의 내용 시각화(도표·그림·화면 디자인) / **AI 학습용 데이터 수집** / 프로젝트 과정 계획·기록·단계별 발표 준비
- **개발자**: 활용 가능한 기술 조사 / 우리 팀이 구현 가능한지 검토 / **AI 알고리즘 선택** / 1차 프로토타입 개발 / 개선 반영 2차 개발 / 성능 향상 및 최종 개발 완성

## 14. 합격을 위한 아이디어 수준과 접근 전략

### 14-1. 이 심사의 실체
심사는 사실상 **① 1~3분 영상 + ② 자막 2,000자 + ③ 역할 기술서 1,600자**, 이 세 개가 전부다.
그리고 5개 심사 기준 중 **3개(협업 의지 / 열정과 태도 / 역할별 역량·경험)** 는 아이디어가 아니라 **사람**을 본다.
→ 아이디어에 100%를 쏟으면 절반을 비우게 된다. **아이디어 : 역할 증명 = 대략 5 : 5**로 배분해야 한다.

### 14-2. 요구되는 아이디어 "수준" — 눈금
| 등급 | 예 | 평가 |
|---|---|---|
| 탈락권 | "AI로 환경오염을 해결하겠다", "AI 챗봇으로 공부를 돕겠다" | 문제가 남의 것이고 범위가 무한대. 동작 설명 불가 |
| 평범 | "시각장애인을 위한 AI 안내 앱" | 착하지만 **이미 존재**하고, 내가 왜 이 문제를 아는지 근거 없음 |
| **합격권** | "우리 반 급식 잔반이 매일 반 통씩 남는다. 3주간 잔반 사진을 찍어 세어보니 특정 반찬 5개에 몰려 있었다. 급식 사진을 찍으면 잔반량을 예측해 다음 주 배식량을 제안하는 모델" | **내가 관찰 → 데이터화 → AI 동작 시나리오**가 한 줄로 이어짐 |
| 상위권 | 위 + "학교 3곳에 물어보니 같은 문제가 있었다" + 개발자면 "티처블머신으로 잔반 사진 200장을 학습시켜 정확도 얼마" 프로토타입 | 참신성 + 실행력 + 확장성 |

**기준선: 중2가 3주 안에 데이터를 직접 모을 수 있는 크기의 문제.**
그보다 크면 허풍, 그보다 작으면 사회적 의미가 없다.

### 14-3. 아이디어 고르는 법 (참신성 = 남이 안 본 문제 > 어려운 기술)
1. **일주일 관찰 일기**를 쓴다. 짜증났던 순간·불편했던 순간만 30개 적는다.
2. 그중 **나만 접근할 수 있는 현장**을 고른다. (내 학교, 내 동아리, 우리 아파트, 내 동생, 내 지병, 내 취미)
   - 심사자가 "이 학생이니까 발견할 수 있었겠다"고 느끼는 순간 참신성 점수가 나온다.
3. **검색해서 이미 상용 서비스가 있으면 버리거나, 각도를 좁힌다.** ("번역 앱" → "우리 학교 다문화 친구가 급식 알레르기 표시를 못 읽는 문제")
4. **"AI가 아니면 안 되는 이유"** 한 문장이 나오는지 확인한다. 규칙(if문)으로 풀리면 AI 주제로는 약하다.
   → 이미지 인식 / 패턴 예측 / 자연어 이해 / 추천 중 어디에 걸리는지 스스로 말할 수 있어야 한다.

### 14-4. 1~3분 영상 구성 템플릿 (권장 배분)
| 구간 | 시간 | 내용 |
|---|---|---|
| ① 장면으로 시작 | 0:00~0:25 | "지난달 ○○에서 이런 일이 있었습니다" — 설명 말고 **구체적 사건 하나**. 가능하면 현장 컷 |
| ② 내가 확인한 근거 | 0:25~0:50 | 몇 번 세어봤는지, 몇 명에게 물어봤는지. **숫자 1개는 반드시** |
| ③ AI 해결 시나리오 | 0:50~1:50 | 입력 → AI가 하는 일 → 출력 → 누가 어떻게 쓰는지. **화면 그림/스케치를 보여주며** |
| ④ 내 역할 | 1:50~2:30 | 기획자/개발자로서 이 프로젝트에서 **내가 맡을 구체적 일** + 그걸 해본 경험 |
| ⑤ 팀과 마무리 | 2:30~3:00 | 모르는 팀원 3명과 어떻게 일할지 + AI 도구 사용 고백(무슨 질문을 했는지) |

**촬영 원칙**
- 본인 얼굴·목소리 필수. 화려한 편집보다 **또박또박한 말·조용한 장소·자막 정확도**가 낫다 (자막이 그대로 심사자료가 되므로).
- 대본을 먼저 글로 완성하고 → 소리내어 읽어 3분 안에 들어오게 깎고 → 외워서 말한다. 읽는 티가 나면 '열정' 점수가 깎인다.
- **AI 도구 사용은 숨기지 말고 구체적으로 밝힌다.** "ChatGPT에 '초등학생도 만들 수 있는 이미지 분류 방법'을 물어 티처블머신을 알게 됐다" 같은 문장은 감점이 아니라 **AI 관심도 증거**로 작동한다.

### 14-5. 역할 선택 전략
- **중복 선택(기획자+개발자)은 유리하지만 조건부.** 양쪽 문항을 모두 채워야 하고 영상에서도 둘 다 설명해야 한다. 개발 경험이 얕은데 중복 선택하면 "개발 언어·툴 버전·구현 기능" 필수 기재에서 내용이 빈다.
- **판단 기준**: 내가 만든 것을 실행해서 남에게 보여준 적이 있는가(스크래치/엔트리/파이썬/앱인벤터/티처블머신 무엇이든). 있으면 개발자 포함, 없으면 **기획자 단독으로 깊게** 가는 편이 낫다.
- 기획자라고 "아이디어만 내는 사람"이 아니다. 요강상 기획자 업무에 **데이터 수집·시각화·발표 준비**가 들어 있다. 설문·인터뷰·그림·발표 경험을 이 이름으로 묶어라.

### 14-6. 역할 기술서 쓰는 법
- 300/500자는 짧다. **형용사를 다 지우고 사건 1~2개로 채운다.** "성실합니다" ❌ → "3개월간 매주 학급 신문을 만들어 12호까지 냈습니다" ⭕
- 협업 문항(300자)이 숨은 승부처다. 심사 기준의 '협업 의지'가 정확히 여기서 채점된다.
  - 좋은 답의 뼈대: **의견이 갈렸던 실제 경험 → 내가 취한 행동 → 결과 → 그래서 이 캠프 팀에서 하겠다는 구체 행동(예: 회의록 담당, 매주 진행상황 공유)**
  - 모르는 사람 4인 랜덤 팀이라는 조건을 인지하고 있다는 걸 드러내면 좋다.
- 개발자 문항은 **개발 언어 / 툴 이름과 버전 / 구현한 기능**을 반드시 적는다. 누락은 곧 감점.

### 14-7. 놓치기 쉬운 실무 포인트
- **접수 시점 학년 기준**이므로 중3이 되면 지원 불가 — 초6~중2 중 마지막 해라면 이번이 마지막 기회.
- 유튜브는 반드시 **'일부공개'**(비공개 ❌, 전체공개 아니어도 됨). 링크가 안 열리면 곧바로 심사 제외.
- 원본 파일(1GB 이하, mp4 등)까지 **반드시** 업로드. 마이페이지에서 마감 당일 23:59까지 교체 가능.
- 역할 기술서는 **홈페이지 다운로드 양식**만 인정.
- 마감일 접속 폭주 경고가 요강에 있음 → **최소 3일 전 제출**.
- 만 14세 이상이면 본인 명의 휴대폰을 미리 준비.
- 학교 단위로 여러 명이 지원하면 **최다 응모 학교상(100만원)** — 3기는 8명 지원으로도 3위 수상. 담임/과학부에 알려 같이 지원하면 상 확률이 높다.

### 14-8. 한 문장 요약
> **"내가 아니면 발견할 수 없었던 작은 문제 하나를, 숫자로 세어보고, AI가 무엇을 입력받아 무엇을 출력하는지까지 말할 수 있으면 합격권이다."**

# 15. 아이템 카탈로그 — 실제로 쓸 수 있는 아이디어 목록

> 규칙: 아이템 하나 = **① 내가 발견한 장면 → ② 내가 직접 모을 수 있는 데이터 → ③ AI가 하는 일 → ④ 출력물/사용자 → ⑤ 역할 매칭**
> 이 5칸이 다 채워지지 않으면 그 아이템은 아직 아이템이 아니다.

## 15-1. 학교 안 (관찰·데이터 수집이 가장 쉬움 — 추천 1순위)

### A1. 급식 잔반 예측
- **장면**: 급식 잔반통이 매일 특정 메뉴일 때만 넘친다
- **데이터**: 3주간 배식 후 잔반통 사진 + 그날 메뉴표 (하루 3장 × 15일 = 45장)
- **AI**: 잔반 사진의 양을 이미지로 등급 분류(적음/보통/많음) → 메뉴별 잔반률 학습
- **출력**: "다음 주 ○○반찬은 배식량 70%로" 제안표
- **역할**: 기획자=사진 수집·메뉴 라벨링·영양사 인터뷰 / 개발자=티처블머신 이미지 분류
- **왜 통하나**: 데이터 수집이 초등생도 가능, 사회적 의미(음식물 쓰레기) 명확, 상용 서비스 없음

### A2. 분실물 매칭
- **장면**: 학교 분실물 함에 주인 없는 물건이 학기말에 박스로 쌓인다
- **데이터**: 분실물 사진 100장 + 분실물 신고 문장("검정 실내화 왼쪽만 잃어버림")
- **AI**: 신고 문장(자연어) ↔ 물건 사진(이미지) 유사도 매칭
- **출력**: "당신 물건일 확률 높은 3개" 알림
- **역할**: 기획자=분류 체계 설계·신고 양식 / 개발자=이미지 임베딩 유사도

### A3. 실내 소음 지도
- **장면**: 우리 반은 조용한데 옆 반 이동수업 시간만 시끄러워 수업이 끊긴다
- **데이터**: 스마트폰 소음 측정 앱으로 요일·교시별 dB 2주 기록
- **AI**: 시간대·요일·날씨로 소음 피크 예측(패턴 예측)
- **출력**: "3교시 목요일 복도 소음 위험" 사전 알림 → 시간표 조정 근거
- **역할**: 기획자=측정 프로토콜·시각화 / 개발자=시계열 예측

### A4. 사물함/우산 무단 사용 감지
- **장면**: 비 오는 날마다 우산이 하나씩 사라진다
- **데이터**: 우산 꽂이 사진 시간별 촬영
- **AI**: 물체 개수 카운팅 + 이상 감소 탐지
- **출력**: 급감 시점 알림, 반별 우산 대여 시스템 설계 근거

### A5. 다문화 친구용 급식 알레르기 리더
- **장면**: 같은 반 외국인 친구가 급식 알레르기 표시를 못 읽어 매번 물어본다
- **데이터**: 급식표 사진 + 알레르기 번호표 + 친구 모국어 단어장
- **AI**: 급식표 사진 OCR → 알레르기 항목 추출 → 모국어로 번역·음성 출력
- **출력**: 사진 찍으면 "오늘 국에 새우 있음" 모국어 음성
- **역할**: 기획자=인터뷰·단어장 구축 / 개발자=OCR+번역 API 연결
- **왜 통하나**: 당사자가 옆에 있어서 인터뷰 근거가 강력함

### A6. 등하교 혼잡 예측
- **장면**: 학교 정문 앞 8시 10~20분에만 차와 학생이 엉킨다
- **데이터**: 2주간 5분 단위 정문 통과 인원 수동 카운트
- **AI**: 요일·날씨·시각별 혼잡도 예측
- **출력**: "오늘은 8시 5분 이전 도착 권장" + 후문 분산 안내

## 15-2. 집·가족 (나만 접근 가능한 현장 — 참신성 높음)

### B1. 할머니 약 복용 확인
- **장면**: 할머니가 약을 먹었는지 매번 헷갈려 다시 먹거나 빠뜨린다
- **데이터**: 약통 사진(먹기 전/후) 60장, 복용 시각 기록
- **AI**: 약통 칸 사진으로 "먹음/안 먹음" 이미지 분류
- **출력**: 가족 단톡방에 "오늘 점심약 미복용" 자동 알림
- **역할**: 기획자=관찰 기록·인터뷰 / 개발자=이미지 분류 + 알림

### B2. 동생 울음 원인 분류
- **장면**: 3살 동생이 우는데 배고픔인지 졸림인지 몰라 엄마가 매번 헤맨다
- **데이터**: 울음 소리 녹음 + 그때 원인 라벨(엄마 확인) 50건
- **AI**: 소리 분류(오디오 → 원인)
- **출력**: "졸림 78%" 표시
- **주의**: 라벨 정확도가 낮을 수 있음 → 영상에서 "라벨이 부정확할 수 있다"고 인지한 티를 내면 오히려 점수

### B3. 냉장고 유통기한 관리
- **장면**: 우리 집은 매달 상한 식재료를 버린다
- **데이터**: 4주간 버린 음식 목록·구매일·버린 날 기록 (엑셀)
- **AI**: 품목별 실제 소비 속도 학습 → 폐기 위험 예측
- **출력**: "우유 2일 내 소비 필요, 이번 주 두부는 사지 마세요" 장보기 리스트
- **역할**: 기획자에게 매우 적합 (데이터가 표라서 개발 난도 낮음)

### B4. 반려동물 이상행동 감지
- **장면**: 우리 강아지가 아플 때 항상 특정 자리에서 웅크린다
- **데이터**: 홈캠 캡처 이미지 + 그날 컨디션 기록
- **AI**: 자세/위치 이미지 분류 → 이상 패턴 감지
- **출력**: "평소와 다른 행동 3회" 알림

### B5. 층간소음 원인 시각화
- **장면**: 아랫집 항의를 받는데 우리 가족은 뭐가 문제인지 모른다
- **데이터**: 방별 진동·소음 시간대 기록
- **AI**: 소리 종류 분류(발소리/의자/문닫힘)
- **출력**: "저녁 9시 이후 의자 끄는 소리가 원인 1위" 가족용 리포트

## 15-3. 동네·이동 (사회적 의미가 크게 보임)

### C1. 인도 위 장애물 지도
- **장면**: 등굣길 인도에 세워진 킥보드 때문에 유아차가 못 지나가는 걸 봤다
- **데이터**: 등하교 경로 인도 사진 200장(2주) + 장애물 유무 라벨
- **AI**: 사진에서 장애물 탐지 → 지도에 위험 지점 표시
- **출력**: 구청 제출용 "우리 동네 보행 방해 지점 지도"
- **왜 통하나**: 결과물이 실제 민원으로 이어짐 = 사회적 의미 최상

### C2. 버스 정류장 대기 스트레스
- **장면**: 우리 정류장은 앱 도착 정보와 실제가 항상 3~5분 다르다
- **데이터**: 2주간 앱 예상 시각 vs 실제 도착 시각 100쌍
- **AI**: 오차 패턴 학습 → 보정된 도착 시각 예측
- **출력**: "앱은 5분이라지만 실제로는 8분" 보정 알림
- **역할**: 개발자 지원자에게 강력 (데이터가 숫자, 회귀 문제로 깔끔)

### C3. 횡단보도 신호 부족 구간
- **장면**: 초등 저학년이 다 못 건너고 신호가 바뀐다
- **데이터**: 보행 신호 시간 측정 + 저학년 보행 속도 측정 30명
- **AI**: 연령·보폭별 필요 신호 시간 예측
- **출력**: "이 횡단보도는 4초 부족" 개선 요청서

### C4. 폐지 수거 어르신 안전 경로
- **장면**: 리어카가 차도로 내려가는 지점이 항상 같다
- **데이터**: 경로별 인도 폭·경사 사진과 측정치
- **AI**: 위험 구간 이미지 분류
- **출력**: 안전 경로 추천 지도

### C5. 우리 동네 쓰레기 배출 오류
- **장면**: 분리수거장에 매주 같은 종류가 잘못 버려진다
- **데이터**: 배출장 사진 60장 + 오분류 라벨
- **AI**: 이미지로 오분류 품목 인식
- **출력**: 촬영하면 "이건 일반쓰레기입니다" + 아파트 게시용 오류 TOP5

## 15-4. 나 자신·건강·공부 (진솔함이 무기, 단 흔해서 각도가 중요)

### D1. 내 편두통 유발 요인 찾기
- **장면**: 나는 한 달에 4~5번 두통이 있는데 원인을 모른다
- **데이터**: 8주간 수면시간·식사·날씨·스크린타임 + 두통 여부 기록
- **AI**: 요인별 중요도 분석(예측 + 특성 중요도)
- **출력**: "수면 6시간 미만 + 흐린 날 조합에서 발생률 3배" 개인 리포트
- **왜 통하나**: 당사자성 최강, 데이터가 표라서 실현 가능

### D2. 필기 인식 오답 노트
- **장면**: 오답 노트를 손으로 다시 쓰는 데만 매일 30분 쓴다
- **데이터**: 내 시험지 사진 100장 + 오답 유형 라벨
- **AI**: 손글씨 OCR + 오답 유형 자동 분류(계산실수/개념/문제 오독)
- **출력**: 유형별 오답 통계 → 취약 개념 순위
- **주의**: "AI 공부 앱"으로 뭉뚱그리면 흔함. **"오답 유형 자동 분류"** 로 좁혀야 참신

### D3. 자세 교정 알림
- **장면**: 숙제 1시간 뒤 목이 아프다
- **데이터**: 웹캠 캡처 200장 + 좋은자세/나쁜자세 라벨
- **AI**: 자세 이미지 분류(또는 포즈 추정)
- **출력**: 나쁜 자세 20초 지속 시 알림

### D4. 감정 일기 패턴
- **장면**: 기분이 나쁜 날에 이유를 설명하지 못한다
- **데이터**: 6주간 일기 텍스트 + 그날 기분 점수
- **AI**: 텍스트 감정 분석 + 반복 키워드 추출
- **출력**: "'시험'과 '늦잠'이 언급된 날 기분 점수가 평균 -2" 리포트

## 15-5. 취미·특수 현장 (참신성 폭발 지점 — 나만 아는 세계)

> 심사자가 "이 학생이니까 발견할 수 있었겠다"고 느끼게 만드는 자리. **본인 취미가 있으면 여기가 최우선.**

| 아이템 | 장면 | 데이터 | AI가 하는 일 |
|---|---|---|---|
| E1. 밴드부 튜닝 도우미 | 합주 전 튜닝에 20분 낭비 | 악기별 소리 녹음 300개 | 소리 → 음정 이탈 판정 |
| E2. 태권도 품새 자가 채점 | 관장님 없으면 틀린 걸 모른다 | 내 품새 영상 50개 + 채점 | 동작 포즈 → 감점 요소 검출 |
| E3. 텃밭 작물 병해 판별 | 상추 잎이 왜 노랗게 되는지 모른다 | 잎 사진 150장 + 원인 라벨 | 이미지 → 병해/영양부족 분류 |
| E4. 낚시·등산 등 안전 판단 | 갈지 말지 매번 감으로 정한다 | 날씨·조위·기록 + 성공 여부 | 조건 → 위험/성과 예측 |
| E5. 레고·프라모델 부품 찾기 | 부품 하나 찾는 데 10분 | 부품 사진 300장 | 이미지 → 부품 번호 식별 |
| E6. 보드게임 초보 코치 | 동생이 규칙을 몰라 매번 짐 | 대국 기록 100판 | 판 상황 → 다음 수 추천 |
| E7. 합창부 파트 배정 | 파트 배정이 주관적이다 | 개인 음역 녹음 40명 | 목소리 → 적합 파트 분류 |
| E8. 사투리/수어 통역 | 할머니 사투리를 동생이 못 알아듣는다 | 음성/영상 데이터 직접 녹음 | 음성 인식 + 변환 |

## 15-6. 아이템 자기 채점표 (제출 전 필수)

각 항목 1점, **7점 이상이면 제출 가능, 5점 이하면 아이템 교체**.

| # | 체크 | 확인 질문 |
|---|---|---|
| 1 | 당사자성 | 내가 직접 겪었거나 눈으로 본 장면을 말할 수 있는가? |
| 2 | 숫자 | "몇 번/몇 명/몇 개" 라는 숫자를 하나라도 세어봤는가? |
| 3 | 데이터 확보 | 3주 안에 내가 직접 모을 수 있는 데이터인가? (사진 100장, 기록 50건 수준) |
| 4 | AI 필연성 | if문·엑셀로는 못 풀고 AI(인식/예측/분류/추천)가 필요한가? |
| 5 | 입출력 명시 | "무엇을 넣으면 무엇이 나온다"를 한 문장으로 말할 수 있는가? |
| 6 | 사용자 | 이걸 실제로 쓸 사람이 누구인지 이름을 댈 수 있는가? |
| 7 | 미존재성 | 검색했을 때 똑같은 상용 서비스가 없는가? (있으면 각도를 좁혔는가) |
| 8 | 역할 연결 | 내가 고른 역할(기획자/개발자)로 이 프로젝트에서 할 일이 구체적인가? |
| 9 | 확장성 | 우리 학교 밖(다른 학교·동네)에도 적용된다고 말할 수 있는가? |
| 10 | 3분 설명 | 3분 안에 위 내용이 다 들어가는가? |

## 15-7. 피해야 할 아이템 (탈락 패턴)

| 유형 | 예 | 문제 |
|---|---|---|
| 스케일 허풍 | AI로 기후위기·교통체증·저출산 해결 | 데이터도 검증도 불가, 관찰 근거 0 |
| 이미 있는 것 | AI 번역 앱, AI 챗봇 과외, AI 사진 보정 | 참신성 0점 |
| 남의 문제 | 아프리카 물 부족, 노인 고독사 (접점 없이) | 당사자성·데이터 없음 |
| 기술 자랑형 | "트랜스포머로 멀티모달 모델을 설계" | 문제 정의가 비고, 심사 5항목 중 1개만 노림 |
| 규칙으로 풀리는 것 | 시간표 알림, 준비물 체크리스트 | AI 필연성 없음 |
| 윤리 리스크 | 친구 얼굴 몰래 촬영, 성적 자동 공개, 특정인 감시 | 데이터 수집 자체가 문제. 초상권·동의 이슈로 감점 |

> **동의 확보를 영상에 언급하면 가점 요소**: "사진은 담임 선생님 허락을 받고 얼굴이 안 나오게 찍었습니다" 한 줄이 태도 점수를 올린다.

## 15-8. 역할별 아이템 추천 매칭

**기획자 단독 지원자 — 데이터가 '표/기록/인터뷰'인 아이템**
→ A1(급식 잔반), B3(냉장고), C1(인도 장애물 지도), C3(횡단보도), D1(편두통)
이유: 직접 세고 인터뷰하고 시각화하는 과정이 곧 기획자 업무 정의(사전조사·데이터 수집·시각화·발표)와 일치

**개발자 포함 지원자 — 프로토타입까지 보여줄 수 있는 아이템**
→ A1/A5(티처블머신 이미지 분류), C2(버스 도착 오차 회귀), D3(자세 분류), E3(잎 병해 분류), E5(부품 식별)
이유: 티처블머신·엔트리·파이썬 수준으로 **영상 안에서 실제 동작 화면**을 3초라도 보여줄 수 있다
→ 영상에 "데이터 200장으로 학습해 정확도 84%가 나왔습니다" 한 문장이 들어가면 역량 항목이 사실상 확정된다

## 15-9. 아이템 → 영상 한 문장 변환 공식

> **"저는 [현장]에서 [구체적 사건]을 봤습니다. [기간] 동안 직접 [데이터]를 모아 세어보니 [숫자]였습니다.
> 그래서 [입력]을 넣으면 AI가 [판단]해서 [출력]을 알려주는 것을 만들고 싶습니다.
> 이건 [사용자]가 쓰게 되고, 저는 [역할]로서 [구체적 업무]를 맡겠습니다."**

**예시 (A1 급식 잔반)**
> "저는 급식 도우미를 하면서 잔반통이 특정 메뉴 날에만 넘치는 걸 봤습니다. 3주간 잔반통 사진 45장을 찍어 세어보니 반찬 5종류에 잔반의 62%가 몰려 있었습니다. 그래서 급식 사진을 넣으면 AI가 잔반량을 예측해 다음 주 배식량을 제안하는 것을 만들고 싶습니다. 이건 영양사 선생님이 쓰게 되고, 저는 기획자로서 사진 수집과 메뉴별 라벨링, 영양사 인터뷰를 맡겠습니다."

→ 이 4문장이 나오지 않는 아이템은 아직 아이템이 아니다.
